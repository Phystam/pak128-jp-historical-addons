# 橋（`obj=bridge`）および交差橋（`obj=crossing`）の画像割り当て・モデリング規約

本リポジトリにおける `bridges/` カテゴリの橋アドオン制作・画像割り当てに関する注意点まとめです（Simutrans 125.0 / `pak128` / `makeobj 60.12` 実機検証済み）。

---

## 1. `ramp` / `ramp2`（スロープ）の向きに注意（`way` と 180° 逆）

`way` の坂画像（`imageup[n/s/e/w]`）と、`bridge` のスロープ画像（`backramp[n/s/e/w]` / `frontramp[n/s/e/w]`）は**向きの定義が 180° 逆**になります。

| 種別 | キー `[n]` の意味 | Blender モデルでの高低（`turns=0`） |
| :--- | :--- | :--- |
| **`way` (`imageup[n]`)** | 北を**向いて下る**斜面（南側が高い） | `Y = +1.0` が `Z = 0`、`Y = -1.0` が `Z = +H` |
| **`bridge` (`backramp[n]`)** | 南岸から**北（`+Y`）の橋へ向かって登る**スロープ | **`Y = -1.0` が `Z = 0`、`Y = +1.0` が `Z = +H`** |

- **`ramp[n]`**: `-Y`（南）が低く、`+Y`（北）が高い
- **`ramp[s]`** (`turns=2`): `+Y`（北）が低く、`-Y`（南）が高い
- **`ramp[e]`** (`turns=1`): `-X`（西）が低く、`+X`（東）が高い
- **`ramp[w]`** (`turns=3`): `+X`（東）が低く、`-X`（西）が高い

> [!WARNING]
> `simutrans_blender_kit` の `GROUP_TURNS["ramp"]` は `way` と同じ `{"n": 0, "e": 1, "s": 2, "w": 3}` を前提としているため、**Blender 側の `ramp` モデル自体を「`-Y` が低い（`Z=0`）、`+Y` が高い（`Z=+H`）」向きで作る**必要があります。逆向きに作るとゲーム内でスロープの方向が反転し、橋桁と断絶します。

---

## 2. `pak128`（`height_conversion_factor = 2`）における `ramp2` の必須対応

`pak128` では地形の 1 段差が **2 段階分（double-height: `2 * H = 0.8165` BU / 32px）** として扱われるため、平地から架橋する際のスロープは 2 段分の高さになります。

- 1 段用: `backramp[n/s/e/w]` / `frontramp[n/s/e/w]`（高さ `H = 0.408248` BU）
- **2 段用**: **`backramp2[n/s/e/w]` / `frontramp2[n/s/e/w]`（高さ `2 * H = 0.816497` BU）**

`ramp2` を省略すると、ゲーム内で 1 段分のスロープ（`ramp`）と 2 段高い橋桁（`span`）の間に 16px 分の段差が生じてしまいます。必ず両方を作成・登録してください。

---

## 3. `pillar`（橋脚）の Z 座標基準と配置位置（前後2分割・端寄せ）

Simutrans では、橋脚（`backpillar[s|w]`）は橋桁の下の地形高さ（または 1 段下の位置）を基準 `Z = 0` として描画されます。

- **Z 座標の正しい範囲**: **`Z = 0.0`（接地・水面の基準面）から `Z = +H`（`+0.40825` BU、結合部は `+0.42` 程度までわずかに重ねる）** まで上向きにモデリングする。
  - `Z = -H .. 0` でモデリングすると、ゲーム内で橋桁と橋脚の間に 1 段分の隙間が生じて橋脚が浮いて（あるいは地下に沈んで）見えます。
- **Y 座標（配置位置）と船舶航路・描画欠け対策**:
  - 橋脚をタイル中央（`Y = 0` や `Y = ±0.50`）に 1 基だけ配置すると、橋の下を通る船と重なって不自然になります。
  - 一方、タイル外周ギリギリやタイル外（`|Y| >= 1.0`）へ押し出すと、`128×128` カメラ枠の端で橋脚がクリップ（描画欠け）します。
  - **推奨解（前後2分割・両端配置）**: 橋脚をスリムな**前後 2 パーツに分割し、タイル両端付近（`Y = -0.82` と `Y = +0.82`）に配置**します。これにより河川中央（`Y ∈ [-0.70, +0.70]`）の航路を完全に空けつつ、`128×128` スプライト枠内に欠けなく収まります（古墳木桁橋・奈良官道木橋で実機確認済み）。

## 4. `back*` / `front*` レイヤ分離と方位ごとの手前・奥判定

車両・歩行者が橋の高欄の内側を正しく通過するよう、手前側の高欄は `front*`、路面・奥側高欄・橋脚は `back*` に分離します。

- `simutrans_blender_kit` のカメラ方位 `az = 45° - 90° * turns` において：
  - `sin(az) > 0`（`turns ∈ {0, 3}`, 例: `ns`, `n`, `w`）: **`+X` 側が手前（`front`）**、`-X` 側が奥（`back`）
  - `sin(az) < 0`（`turns ∈ {1, 2}`, 例: `ew`, `e`, `s`）: **`-X` 側が手前（`front`）**、`+X` 側が奥（`back`）
- 単純に非表示で別撮りすると影や境界が欠けるため、反対側を `ShaderNodeHoldout` マテリアルでマスクして 2 パスレンダリングすることを推奨します。

---

## 5. 積雪画像（`[0]` / `[1]`）の対応状況

- **`obj=bridge`**: 積雪画像に対応。**通常画像にも必ず `[0]` を付けた上で** `[1]` を登録する（例: `backimage[ns][0]=...` と `backimage[ns][1]=...`）。
- **`obj=crossing`**: `makeobj 60.12` 仕様上、季節・積雪インデックスに非対応（`openimage[ns][0]` の `[0]` はアニメーションフレーム番号）。`.dat` には通常画像のみを登録し、積雪画像（`*_snow.png`）は将来拡張・参照用として同フォルダに保持する。
